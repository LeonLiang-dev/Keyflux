## Observed hardware result

The explicitly authorized manual test passed on USB Air75 V3 ANSI, firmware
**1.0.23.6**, Mac profile, Apple Silicon macOS. Script:

```sh
python3 scripts/test-air75-main-macos.py --evidence docs/evidence/air75-v3-main-20261102.json
```

| Request at 15% | Independent D5 RGB | Result |
| --- | --- | --- |
| Red `#FF0000` | `[255,0,0]` | Exact |
| Cyan `#00FFFF` | `[0,255,255]` | Exact |
| Purple `#8000FF` | `[132,0,255]` | Exact byte-HSV projection |

Each color was followed by a separate read-only CLI probe whose full state
equaled the mutation's reported state. Repeated cyan returned `changed:false`.
Bytes 9–21 were unchanged throughout. Final restoration matched all **22**
initial bytes and `hardware-status-air75` confirmed no recovery record remained.
The original was stock effect 6 at brightness 50, not a custom palette.

**Visual acceptance is unconfirmed.** The user reported “没留意颜色变化”. No
claim is made about observed physical colors, optical RGB accuracy or perceived
animation restoration. [Sanitized raw evidence](../evidence/air75-v3-main-20261102.json)
contains no serial, path, location or fingerprint.

## Implementation and software checks

- Separate read and main-setter native entry points. The read path still rejects
  D6; the main path rejects every opcode other than D6 and every side/palette
  range, wrong profile, unsupported original mode and malformed envelope.
- Atomic/fsynced pending journal before setters; first capture retained across
  colors. Unknown identity/profile/firmware, external unowned changes and corrupt
  records cannot replace recovery data. Removal follows exact verification.
- Core/native boundary tests passed with `zig build test -j2`. New tests cover
  save-before-write ordering, failed saves, pending recovery, duplicate colors,
  original capture retention, lost ACK, mismatched readback, concurrent edits,
  foreign identity, unowned changes, inverse RGB recovery and JSON roundtrips.
- Native macOS ReleaseSafe build and Zig formatting passed.
- Windows cross-compilation passed; native Air75 control remains macOS-only
  and no Windows physical keyboard test was performed.
- **14** simulated integration tests and **3** workflow tests passed. Parameter
  rejection occurs before HID; existing Kick75/simulated workflows still pass.
- Both model descriptors validate. Air75 is `experimental`, with only manual
  main solid/readback/recovery capabilities and a pinned platform/firmware matrix.

Inverse RGB selection and interruption/failure paths were software-tested;
this physical pass restored the original black RGB/configured stock effect.
It did not perform a physical power-loss, SIGKILL, sleep/wake or hotplug test.

## Scope limits

The desktop UI/Rust bridge and AI follower are unchanged. Per-key/side setters,
keymap, firmware, EE key changes and D8 palette writes remain unavailable.
Wireless, Windows hardware, flash persistence and sustained-write safety remain
unverified. No full UI suite or optical measurement was run. The manual command
is for controlled experiments, not an assertion of general Air75 support.
